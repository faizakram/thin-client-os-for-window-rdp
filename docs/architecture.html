Debian 13 · FreeRDP appliance

How the ThinClient OS works, end to end.

A single-purpose operating system that boots straight into a full-screen Windows RDP session and nothing else — no desktop, no shell, no login prompt. Below is the complete architecture: from power-on to the remote desktop, and every supervisor, gate, and lockdown that keeps it there.

base Debian 13 (Trixie) client FreeRDP 3 · xfreerdp3 init systemd → graphical.target wm Openbox on Xorg VT7 boot BIOS + UEFI hybrid link RDP / TCP 3389 · NLA+TLS user one locked account, no sudo
system / boot config & control healthy · connected supervisor · recovery blocked · locked

Config-driven RDP

The connection is never hard-coded. rdp-build-args.sh reads server.conf on every attempt, validates it, and maps each toggle to an xfreerdp3 flag. The password is streamed over stdin — never argv — so it can't appear in ps.

Network gate & WiFi

Before hammering RDP, the session confirms it has a network. Ethernet and any baked WiFi get a grace window; if the box is still offline, a locked-down WiFi picker appears — it can only join WiFi, so anyone at the machine can reconnect without exposing a desktop.

Admin Mode — the hidden door

The only way in is the secret hotkey plus the admin password (stored as a SHA-512 hash, with a lockout). Every action returns to the RDP session; closing the menu returns focus to Windows.

FIG.07

Security lockdown

Deny-by-default. The machine can do exactly one thing — run the RDP client — and everything that could break out of it is removed or masked.

■ Blocked / removed

getty@tty1–6 → /dev/null DontVTSwitch DontZap Ctrl+Alt+F1–F12 Alt+Tab · Alt+F4 no terminal no file manager no SSH server root: locked · nologin user: nologin · no sudo kernel.sysrq = 0 screen blank / DPMS off

■ Allowed

full-screen RDP session device redirection (per config) join WiFi (picker) admin hotkey → password gate scoped sudo: session ctl scoped sudo: reboot/poweroff scoped sudo: apt update/upgrade scoped sudo: nmcli / nmtui

Credentials never travel in cleartext (NLA + TLS) and never hit the process table (password via stdin). A stored password/WiFi key is recoverable from the raw disk — so built images are treated as secrets.

MAP

Where everything lives

The on-disk layout of the appliance — programs, configuration, logs, and runtime state.

/opt/thinclient/bin/Runtime programs — session loop, watchdog, splash, WiFi picker/gate, admin tools, config CLI, diagnostics.
/opt/thinclient/lib/Shared Bash libraries — the safe config parser and the FreeRDP argument builder.
/etc/thinclient/server.confThe single source of truth: server, credentials, device toggles, WiFi, reconnect.
/etc/thinclient/admin.confAdmin password hash + secret hotkey (root-only, 0600).
/etc/systemd/system/thinclient-*.serviceThe three units: firstboot, kiosk X session, watchdog.
/etc/X11/ · /etc/sudoers.d/thinclientXorg kiosk hardening, X wrapper policy, and the scoped sudo allowlist.
/var/log/thinclient/Rotated logs — boot, rdp, watchdog, network, install.
/run/thinclient/Runtime state — heartbeat timestamp and session state for the watchdog.
